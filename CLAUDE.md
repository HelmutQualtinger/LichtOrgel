# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

LichtOrgel is an audio-driven "light organ": a single self-contained file, `index.html` (HTML + CSS + JS, no build step, no dependencies, no package.json), published via GitHub Pages (https://helmutqualtinger.github.io/LichtOrgel/, repo HelmutQualtinger/LichtOrgel). It is also an installable PWA: `manifest.webmanifest`, `sw.js` and the icons. The UI text and code comments are in German; keep them German.

## Running

Microphone access (`getUserMedia`) needs a secure context, so serve over localhost rather than opening the file directly:

```sh
python3 -m http.server 8000   # then open http://localhost:8000 (avoid port 5000: macOS AirPlay)
```

URL parameter `?gpu=webgpu | webgl | off` forces a render backend (useful for comparing backends or testing the Canvas 2D fallback).

## Verification (no test suite)

- Syntax check: extract the `<script>` body and run `node --check` on it.
- Headless Chrome via `--dump-dom` works for synchronous checks (call `applyMode(name)` + `drawVisual(fakeLevels)` from an injected script). Do **not** use `--virtual-time-budget` for WebGPU: virtual time makes async shader compilation appear to hang. For WebGPU, drive real-time headless Chrome over the DevTools protocol (`--remote-debugging-port`, `Runtime.evaluate` with `awaitPromise`) and take screenshots with `Page.captureScreenshot`.
- Chrome flags `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream --auto-select-desktop-capture-source=Entire` let headless runs exercise both the mic and the screen-share path (served over `http://127.0.0.1`, not `file://`). Real microphone input can't be tested headless; `Oszilloskop`/`Wasserfall` and the GPU uniform values only get real data with a live mic.

## Architecture

One `requestAnimationFrame` loop, `drawLevels()`, runs while the mic is active:

1. **Audio**: source menu `#source` (persisted as `lichtorgel-source`), three optgroups: inputs, synthesizer loops, own music. Inputs: default mic, any `audioinput` device (e.g. a BlackHole loopback), or `system` = computer sound via `getDisplayMedia` (Chrome/Edge only; video track is stopped immediately, user must tick "Share audio"). `openStream()` picks the API; processing (echo cancellation, noise suppression, auto gain) is deliberately **off** for low latency. Computer sound is shifted by `systemOffsetDb` (−20 dB) because a digital signal is much louder than a mic. Music: `file` = own audio file via a hidden file input; `startMusic()` plays it in a loop through an `Audio` element → `createMediaElementSource` → analyser → `musicGain` → `destination` (audible) and sets `stream` to an empty `MediaStream` as the "audio is running" marker that the rest of the code checks. Internet radio (re-added on request): `radio:<id>` = six psychedelic SomaFM streams from `radioStations` plus public stations from `radioChannels` (Ö3, ORF Wien/Vorarlberg, Bayern 3, SWR3, Rai Radio 1/2, RSI Rete Uno/Due; own optgroup, each with a fixed `url`; Rai uses the redirect target directly because icestreaming.rai.it redirects without a CORS header). Every stream must send `Access-Control-Allow-Origin` and be https. The page sets `<meta name="referrer" content="no-referrer">` because SomaFM answers 403 to a localhost/github.io Referer. SomaFM: (`Access-Control-Allow-Origin: *`, needed with `crossOrigin = "anonymous"`; SomaFM answers 403 without a browser User-Agent, so test headless with `--user-agent`); `startMusic()` reconnects on `ended`/`error`/15 s stall, rotating `streamHosts`, max 12 attempts. Radio is never autostarted (autostart always picks a synth). Synth group: `synth:<id>` = generative loops from `synthPresets` (goa, forest, psydub, raga, sixties, krautrock, kosmos, bowls; object order = menu order, first = autostart default), built by `createSynth()` purely with Web Audio (voices: kick, noiseHit, synth incl. `type: "organ"` periodic wave, pluck, drum, snare, bowl) (oscillators, filters, noise buffer, convolver reverb from a generated impulse, filtered feedback delay). Signal chain: voice buses (`makeBus` dry/delay/reverb sends) → per-preset `gain` → glue compressor → limiter (−3 dB, ratio 20) → `synth.output` → analyser. A 25 ms `setInterval` schedules 16th-note steps ahead on the audio clock (`preset.step(state, step, time, voice, stepDur)`), with a longer horizon while the tab is hidden. `startSynth()` waits for a user gesture itself if the context can't start. `startMusic()` plays an `Audio` element through `createMediaElementSource` → analyser → `destination` (audible) and sets `stream` to an empty `MediaStream` as the "audio is running" marker that the rest of the code checks. Autostart: page load always enables auto mode and calls `autostart()` with a synthesizer loop (the saved one if a synth was last chosen, else the first preset, Goa); no mic permission is requested at load. If the browser blocks sound or speech until a user gesture, the first pointerdown/keydown unlocks it. Resilience: `watchStream()` auto-reconnects a mic whose track ends (device change, AirPods, sleep; falls back to the default mic if the device vanished), the `AudioContext` is resumed on `statechange`/`visibilitychange`, and `drawLevels()` schedules the next frame before rendering and catches per-frame errors, so a throwing mode can't kill the loop. Any user action bumps `reconnectToken` to cancel a pending reconnect. → `AnalyserNode` (`fftSize` 1024, `smoothingTimeConstant` 0). Latency was a user complaint; don't raise FFT size or smoothing without reason.
2. **Bands**: 10 log-spaced bands, 40 Hz–16 kHz, power-averaged in dBFS and clamped to `minDb` −90 … `maxDb` −30. There is no level meter display anymore (removed on request); the bands only feed the visualization.

**Layout**: one compact header bar (title, mic toggle, status, `<select>` menus for mode and theme, backend/fps label) above `#vis-stage`, which fills the rest of the viewport (`100dvh`, page never scrolls). A `ResizeObserver` on the stage resizes both canvases.
3. **Visualization**: `drawLevels()` calls `drawVisual(levels)`, which normalizes levels into `visLevels` (0..1; instant attack, 0.25 decay), derives `bass`, `overall`, `dominant` and a `beat` flag (bass jump above its running average), then renders the selected mode. Called with no argument it draws the idle state (mic off, theme/mode switch, resize).

### Modes, themes, backends

- `themes` — palette objects (`bg`, three `colors`, `core`, `glow`). Adding an entry auto-creates its menu option.
- `modes` — Canvas 2D implementations `(ctx, w, h, theme, state)`. Each mode clears or fades the canvas itself (`fade()` uses `destination-out` for trails). Per-mode scratch state lives in `fx`, which `renderModes()` points at `fxStore[mode]` before each call (two modes can run at once); `resetModeState()` clears it when a mode is entered. Modes must draw via their `ctx`/`ctx.canvas`, never `visCanvas` directly. Adding an entry auto-creates its menu option.
- `gpuShaders` — optional GPU versions of a mode, keyed by the same name. If the active backend is GPU and a shader exists, it is used instead of the 2D mode on a stacked `#visual-gpu` canvas.
- Backend chain in `initGpu()`: WebGL2 → WebGPU (4 s timeout) → Canvas 2D; `?gpu=webgpu` tries WebGPU first. WebGL2 is the default because it measured ~1.7× faster than WebGPU for these shaders (Mandelbrot, Apple M1). A canvas keeps its first context type, so a failed attempt calls `freshGpuCanvas()` before trying the next.

### Mode crossfades, auto mode and theme blending

- Mode changes (manual and auto) go through `transitionTo()`: for `modeBlendMs` (2.5 s) the old and new mode render simultaneously in `renderModes()`. 2D+2D uses the two 2D layers (`#visual`, `#visual-b`) with opposite opacity; GPU+GPU draws both shaders in one pass, the new one blended via a blend constant (WebGPU: background-built `blendPipelines`, WebGL: `CONSTANT_ALPHA`); GPU+2D fades the GPU canvas, which lies on top. The theme background gradient sits on `#vis-stage`, so 2D layers stay transparent. `applyMode()` switches instantly (init, idle).
- `#auto` toggle (persisted as `lichtorgel-auto`). `autoStep()` runs inside `drawVisual()`, so it only advances while audio is running. Every `autoModeMs` (20 s) it crossfades to the **next** mode in menu order on the next bass beat (at most 3 s late); every `autoThemeMs` (12 s) it blends to the next theme in order.
- Theme changes (auto and manual) go through `blendToTheme()`. Modes and `renderGpu()` must read the theme from `currentTheme()` (passed in as `t`), never `themes[themeName]` directly: during a blend `currentTheme()` returns an interpolated theme object with hex colors. Caches derived from theme colors must key on the colors (see Plasma's LUT), not on `themeName`.
- Choosing a mode or theme by hand resets the auto schedule.
- Speech (`#speech` toggle, `lichtorgel-speech`): on every theme change (auto mode) or every `sayingEveryMs` (30 s, `speechStep()`, when auto is off) `speakNext()` speaks one of the 31 sayings of the current language via `speechSynthesis` (rate 0.72) and shows it in `#caption`. Order is a Fisher–Yates shuffle consumed without repeats, reshuffled when empty. `pickVoice()` takes the first German voice matching `femaleVoices` (Premium/Enhanced preferred). Speech can't be louder than `volume = 1` and bypasses Web Audio, so for music sources `duckMusic()` lowers `musicGain` (after the analyser, so the visuals are unaffected) to `duckLevel` 0.25 while speaking. `speak()` needs prior user activation, which the Auto/Start clicks provide. `stopSpeech()` runs on speech off and `stopAudio()` (not on auto off: speech works without auto mode); `setAuto(autoOn)` is called only after the speech block because `stopSpeech` touches `caption`.

### Shader authoring rules (important)

Shaders are written **once** in a restricted GLSL subset (`shaderLib` + each `gpuShaders` entry, with a `vec4 shade(vec2 fc)` entry point, `fc` in device pixels with top-left origin). WebGL2 uses them as-is; for WebGPU `toWGSL()` converts them with regex. Code must therefore follow:

- every declaration typed (`float x = ...`), no implicit int→float; floats always written with `.0`
- braces on every `if`/`for`; no ternary operator; no swizzle assignment; never assign to function parameters
- use `atan2` and `fmod` (defined in both preambles), not `atan(y,x)`/`mod`
- helper functions must be defined before use (GLSL order)
- avoid GLSL/WGSL reserved words as identifiers (e.g. `half`, `sample`, `filter`, `in`, `out`)

Uniforms are one `vec4 u[20]` array (layout documented in the comment above `shaderLib`); `renderGpu()` fills it. Both preambles also provide `orbitAt(int i)`, reading an RG32F 1024×4 texture (WebGPU binding 1, WebGL texture unit 0).

Mandelbrot zoom targets are **minibrots at the end of a chain** ("Julia morphing", requested so the zoom doesn't stay in self-similar regions): `makeTarget(i)` → `minibrotChain()`: level 1 looks near Misiurewicz spot A (offsets `chainRel[0]` = 1e-2/3e-3/1e-3) for minibrot M1; level 2 maps the copy of a *different* spot B into M1 via its complex scale σ (c = N + σ·C, offset 1e-3) and finds M2 there. The zoom then passes spiral A → doubled stars around M1 → M1 → structure B → doubling again → M2. Period via the ball method (`findPeriod()`), nucleus via Newton (`nucleus()`: z in BigInt, derivative in double; `numToFixed()` converts tiny doubles without precision loss), complex size/orientation via Heiland-Allen 1/(b·l²) (`miniScale()`). Constraint is the period, not depth: around a minibrot of period p pixels need ~4–5 p iterations on average, >10 p at the edge, so `chainMaxPeriod` = 400 (targets end around 1e-8…1e-16, typically 1e-11; deeper chains had p ≈ 1000–4000 and dropped to 2–15 fps). `maxIt` adds `miniIterFactor` (12) × p, ramped in by (depth/end)², capped at `maxIterCap` 8000 (shader loop bound 8192; rebasing restarts the reference orbit, so `orbitMax` is not a limit). End view = `-log10(|size|) - minibrotFrame` (0.3). A full two-level chain succeeds in 15–50 % of tries (a few ms each); `makeTarget()` tries 10 times, else takes a level-1 minibrot, else (and always without GPU, since the 2D fallback caps at 450 iterations) the plain Misiurewicz spot with `endDepth` = `mandelDepth`. Targets are re-rolled on every visit (`targetCache`: `prepareTarget()` 1 s after a switch, `takeTarget()` consumes it). State machine in `mandelStep()`: `pan` (offset `panVec` eased to 0) → `in` to `mandel.end` (the target's `endDepth`), or earlier when the image gets too uniform (frame > 90 % interior, or `mandelScan()` sees fewer than `flatSpread` (8) iteration steps between the 5th and 95th percentile for two scans in a row, `mandel.flat`) → `hold` (8 s at the minibrot) → `out` → next spot. A click (`mandelClick()`) sets `mandel.end` = `mandelDepth` (1e-30). Interior pixels are rendered exactly black (exterior gets +0.012), and every 45 frames while zooming in `renderGpu()` sets `gpuState.wantStats`: both read back asynchronously (WebGL: `readPixels` into a PIXEL_PACK_BUFFER + fence, fetched in a later frame; WebGPU: canvas texture configured with COPY_SRC copied to a mapped buffer); `blackShare()` (every 7th pixel) → `mandelReport()`. The 2D fallback reports from its own pixels. `mandelScan()` (48×28 CPU grid, 2 rows per frame) only feeds the color mapping. A click on the stage (`mandelClick()`) makes the clicked point the new reference: its BigInt coordinates are the old reference's `cx`/`cy` plus the double offset scaled to fixed point, so it stays exact at depth; velocity eases smoothly; the method itself works to ~1e-30). Mandelbrot uses the theme's 8-stop `fractal` colormap (every theme needs one; `currentTheme()` blends it; uploaded as u[12..17]; cyclic (modulo 1, last stop blends back into the first), `heatCycles` = 2 cycles over the *visible* iteration range (linear): `mandelScan()` also measures the 5th–95th percentile of escaped samples, smoothed into `colorK`/`colorOff` = u[11].y/.w; `colorOff` also adds `mandel.hue` (time, loudness, beat kick), `mandel.vol` × 0.9 (loudness, unsmoothed = instant, shifts the colormap directly; zoom speed deliberately does **not** depend on loudness) and `mandel.pitch` × 1.5 (spectral centroid, unsmoothed of the bands, 0..1); GLSL `heat()` reads the stops). Relief shading: the shader and `mandelIter()` also carry dz/dp (der' = 2·z·der + dc/dp); normal = z/der, light from the upper left; the distance estimate 0.5·|z|·ln|z|/|der| (in pixels) blends sub-pixel detail (below ~0.6 px) into a dimmed mix of the palette color and the palette average, so it still follows the colormap without much noise: `mandelSpots` are Misiurewicz points as 50-digit strings; `referenceOrbit(cx, cy)` (BigInt) iterates the target with BigInt fixed point (200 bits) on the CPU, the backends upload `mandel.ref.f32` into the orbit texture when `mandel.version` changes, and the shader (and the 2D fallback, in doubles) iterates only the per-pixel delta (perturbation) with rebasing when |z| < |dz| or the reference orbit ends. `mandelStep()` advances the zoom once per frame; while Mandelbrot is on, `renderGpu()` adapts the GPU canvas resolution to the frame rate (`gpuState.mandelRes`, 0.6…1); u[10..11] carry offset, scale, max iterations, rotation, color step, orbit length and color offset; u[12..17] the colormap, u[18] its average color (both uploaded every frame for every mode; Kaleidoskop's `vivid()` also uses the colormap, brightness-normalized and mixed 60 % with a rainbow, and colors only once after summing brightness plus a weighted hue, with a hue-preserving tonemap, because summing differently colored layers turns gray; the 2D version uses `vividRgb()`), u[19].xy the reference point (main-cardioid and period-2-bulb test skips interior pixels at shallow depth). float32 deltas stop working below ~1e-36, so don't push `mandelDepth` (the cap for click targets and the Misiurewicz fallback) much past 30. After changing a shader, verify it compiles under **both** `?gpu=webgpu` and `?gpu=webgl`.

### Languages (UI and voice)

- The flag menu `#lang` (`lichtorgel-lang`, default from `navigator.language`) sets UI **and** voice language: `uiText[de|en|it]` holds all UI strings, `tr(key, ...args)` looks them up (functions for strings with parameters). Static HTML uses `data-i18n`, `data-i18n-title`, `data-i18n-aria`; `applyUiLang()` re-renders those, the menus (`relabelMenus()`, `fillSources()`) and the current status.
- `setStatus(key, active, ...args)` takes a **translation key**, never literal text, so a language switch can re-translate the visible status.
- Mode and theme keys stay German internally (saved settings, `gpuShaders`); `modeLabel()`/`themeLabel()` translate only the displayed names.
- `languages[lang]` holds the 31 `sayings` and the preferred female `voices` per language. Speech fires on every **theme change** (auto and manual) and every 30 s when auto is off, not on mode changes.
- `applyUiLang(uiLang)` runs at the end of the script, because it needs the source menu and status helpers defined further down.

### PWA and mobile

- `sw.js`: page navigations are network-first (`cache: "no-cache"`, bypassing GitHub Pages' 10-minute HTTP cache; the cache is only the offline fallback), so a deploy shows up on the next reload; other assets (icons, manifest) use stale-while-revalidate (cache name `lichtorgel-v1`). With the old pure stale-while-revalidate, deploys appeared only after several reloads. it is registered only over `https:` so local development is never cached. Add new top-level files to `ASSETS` in `sw.js`; bump the cache name only when files are removed or renamed.
- No Xcode/Android SDK on this machine; native store builds (e.g. Capacitor) would need them plus developer accounts.
- Phones: `isMobile` (`pointer: coarse`) caps canvas resolution (2D 1.5×, GPU 1.25×) and shortens the synth reverb (1.8 s) to keep the audio thread from underrunning; music contexts use `latencyHint: "playback"` (mic keeps `"interactive"`); the synth scheduler re-syncs instead of cramming late notes (prevents clicks). Safe-area insets pad `main` (`viewport-fit=cover`).

### Persistence

Selected theme and mode are stored in `localStorage` (`lichtorgel-theme`, `lichtorgel-mode`) via `loadSetting`/`saveSetting`, wrapped in try/catch.
